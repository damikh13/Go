Канал (`ch := make(chan string)`) — способ передачи данных между горутинами. Его можно передать в функцию не по указателю: копия канала ведёт в тот же канал.

Главный принцип их работы: “Читатель блокируется, пока данные не появятся. Писатель блокируется, пока данные не прочитали.”

Базовый пример небуферизированного канала:

```go
ch := make(chan int)

go func() {
	time.Sleep(1 * time.Second)
	fmt.Printf("sending value %v to channel\n", 1) // 2nd
	ch <- 1
}()

fmt.Printf("waiting for sender...\n") // 1st
val := <-ch // BLOCK UNTIL 2nd
fmt.Printf("got value %v from channel\n", val) // 3rd
```

Т.к. мы блокируемся, то может возникнуть ситуация, когда получатель вызван раньше отправителя в **одной** горутине:

```go
func main() {
	ch := make(chan string)
	fmt.Println(<-ch) // заблочили, ждём пока ДРУГАЯ горутина прочитает
	ch <- "some value" // никогда не доходим до сюда!
}
```

Помимо небуферизированных каналов, есть каналы с буфером:

```go
ch := make(chan int, 2) // cap = 2, len = 0

ch <- 1 // не блокируется
ch <- 2 // не блокируется

go func() {
	<- ch
}()

ch <- 3 // блокируется, пока горутина не прочитает
```

> len и cap обычно никто не измеряет. len может измениться после прочтения.

При использовании буферизированных возникает вопрос: “А как выбрать capacity?”. Ведь её выбирают один раз, а менять нельзя.

## Закрытие канала и range

По каналу можно проходиться, используя `for v := range ch`. Фактически, данный код раскрывается в:

```go
for {
	order, ok := <-orders
	if !ok { break } // сработает только тогда, когда канал закрыт && в нём не осталось значений

	// тело цикла
}
```

Пример: вернём канал, доступный только для чтения (проверяется компилятором, что только читаем и не пробуем писать). В него отдельная горутина будет класть значения. Как только она закончит, то канал закроется.

```go
ch := gen(3)
for v := range ch {
	fmt.Println(v, " ")
}
```

```go
func gen(n int) <-chan int {
	ch := make(chan int)
	go func() {
		defer close(ch)

		for i := range n {
			ch <- i
		}
	}()

	return ch
}
```

Когда закрыли канал, можем из него только читать! Остальное поведение — паника!

- `close(закрытый_канал)` = `panic`
- `закрытый_канал ← значение` = `panic`.

Значит, закрывать канал нужно в единственном месте.

Если отправитель всего один, всё легко. Он сам знает, когда заканчивает писать и может закрыть канал:

```go
ch := make(chan int)

go func() {
	defer close(ch) // sender closes when it's done
	for i := range 5 {
    ch <- i
	}
}()

for v := range ch {
	fmt.Println(v)
}
```

Если отправителей несколько, нужно дождаться, пока они не закончат работу:

```go
ch := make(chan string)
var wg sync.WaitGroup

for i := range 3 {
	wg.Go(func() {
		for j := range 3 {
			val := fmt.Sprintf("i=%v, j=%v", i, j)
			ch <- val
		}
	})
}

go func() {
	wg.Wait()
	close(ch)
}()

for val := range ch {
	fmt.Printf("val = %q\n", val)
}
```

# select и timeout

`select`: сработает та ветка, которая может выполниться в данный момент, не блокируясь:

- для небуферизированного канала: только что другая горутина что-то записала
- для буферизированного канала: в буфере есть хотя бы одно значение
- канал закрыт: чтение из такого канала не блокируется — оно всегда возвращает нулевое значение и `ok == false`.

```go
ch := make(chan string)
go func() {
	time.Sleep(200 * time.Millisecond)
	ch <- "1st"
}()

select {
case v := <-ch:
	fmt.Println(v)
case <-time.After(100 * time.Millisecond):
	fmt.Println("timeout") // сработает
}
```

- но тогда не сработает `v := <-ch` ⇒ горутина будет постоянно ждать, пока кто-то не прочитает из канала
- если оба case’а готовы одновременно, выберется случайный

Значение default нужно для одной попытки сделать что-то. Нет смысла делать while true:

```go
ch := make(chan struct{})

go func() {
	time.Sleep(100 * time.Millisecond)
	close(ch)
}

spins := 0
for {
	select {
	case <-ch:
		fmt.Println("итераций:", spins)
	default:
		spins++
	}
}
```

# nil-канал выключает ветку select

```go
a, b := gen(2), gen(1)
for a != nil || b != nil {
	select {
	case v, ok := <-a:
		if !ok {
			a = nil // выключили ветку таким синтаксисом
			continue
		}
	}
	case v, ok := <-b:
		...
}
```
